## Read-once component recurrence

For a positive row `p` and a negative row `n`, form the set of primitive tokens true on `p` and false on `n`. Every monotone formula accepting `p` and rejecting `n` must contain a token from this set. An empty set rejects the instance. A single primitive that separates every pair suffices.

At an OR root, each positive row must be accepted by one child, which must reject every negative row. For that positive row, every token uniquely separating it from some negative row must therefore occur in this same child. Join these tokens, then take the equivalence relation generated by all such joins. Both child token sets are unions of these components. At an AND root use the transpose: one child must reject a given negative row while accepting every positive row. The algorithm enumerates all unordered bipartitions of the resulting components, then all assignments of rows to the feasible child or children. It recursively checks the two child obligations. The same reasoning holds after any recursive restriction of rows and available tokens. With at most twelve tokens, or with more than twelve components, the implementation delegates to the earlier multiset recurrence. Unused leaves and inputs having equal truth tables are allowed in the feasibility check.
