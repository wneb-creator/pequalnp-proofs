The parser reads a fixed compressed prefix of the active stdout.gz through zlib.decompressobj(31); a gzip trailer is not required. Only FP_VECTOR_END-terminated blocks with all thirteen unique cofactor indices are accepted. Each modular polynomial is parsed by strict arithmetic token rules and independently multiplied by the original audited thirteen generators. Slot8 must be zero. Sparse monomials use eleven packed byte exponents internally; every input exponent is required below128, so adding a generator monomial cannot carry into a neighboring variable.

The report distinguishes exact finite-field identities from exact rational identities. CRT and bounded rational coefficient reconstruction are only candidate generators; a rational candidate is labeled successful only after a complete exact Fraction-polynomial identity check. Rational output uses variable_order and cofactors[{terms:[[coefficient_string,exponents],...]}]. Finite-field exports add modulus and an explicit modular-only scope. Exports are lossless gzip JSON, capped at8MiB combined by default and further capped to retain16MiB free space. The raw stream remains authoritative: each report records the fixed compressed prefix length/hash and each complete block's uncompressed byte offsets/hash. Large duplicate exports can therefore be skipped without losing the block.

Run with --selftest --scan PATH_TO_ACTIVE_STDOUT_GZ. The program caps its own address space at384MiB and CPU at90seconds. It may stop inconclusively on larger vectors; it never treats a failed/incomplete parse, a modular identity, or coefficient reconstruction alone as a rational proof.

Self-tests cover signed rational monomials, cancellation, scalar rational reconstruction, CRT, exact modular/rational identities, a complete block with missing gzip trailer followed by an incomplete block, and enforced output byte budget. Initial live scan found no complete blocks. No CAS or Lean build is run by this script.
